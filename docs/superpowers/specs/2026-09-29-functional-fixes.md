# AdNote 功能缺陷修复规格（v0.4.x）

日期：2026-09-29
状态：基于 v0.4.0（commit 77ab807）代码审查得出，决策项均为默认选择，可推翻。
对应计划：`docs/superpowers/plans/2026-09-29-handoff.md`

## 1. 背景

对 v0.4.0 做了一次完整功能审查（见对话记录），共识别出 18 个功能问题。本规格把其中
**14 个可修复、可测试** 的问题整理成明确需求，另外 4 个记为「暂不处理」并说明原因。

## 2. 全局约束

- 构建：JDK 17，compileSdk 34，targetSdk 30，minSdk 26，Kotlin 2.0.20，Gradle 8.9。
- **不新增第三方依赖**（不引入 WorkManager、Room、XML 库）。PROPFIND 的解析用 JDK 自带的 `javax.xml.parsers`。
- `model`、`ink`、`export`、`sync`、`storage` 包继续保持不依赖 Android Framework，所有新逻辑必须能在 JVM 单元测试跑通。
- 已有的 146 个单元测试必须继续通过（`./gradlew testDebugUnitTest`）。
- 数据格式向后兼容：新增的 JSON 字段一律带默认值；旧 `note.json` 与旧 `ink.json` 必须能被新版本读取。
- UI 文案用简体中文，风格与现有对话框一致（`AlertDialog` + `Toast`）。

## 3. 需求

### 3.1 数据安全（子系统 A：同步可靠性）

| 编号 | 问题 | 需求 |
|---|---|---|
| A-restore | 只上传 `ink.json`，没有恢复入口 | 设置页新增「从云端恢复笔记」：扫描远端目录树，列出所有 `_ink/<id>/ink.json`，标注「本地不存在 / 本地较旧 / 已是最新」，用户勾选后下载笔记及其附件（图片、背景、录音、PDF）到本地。 |
| A-assets | 远端 `_ink` 目录不完整：图片、背景图、PDF 原文没上传；删除的录音不会从远端删除 | 同步时把笔记引用的所有附件上传到 `_ink/<id>/` 下（每个附件只传一次），本地删掉的附件在远端也删掉。`SyncState.uploadedAssets` 记录路径；旧字段 `uploadedRecordings` 只读兼容。 |
| A-lock-search | 锁定笔记的正文能被搜索命中 | 锁定笔记只按标题匹配搜索词，不再匹配识别文字、文字框、书签、Obsidian 正文。 |

### 3.2 Obsidian 互联（子系统 A）

| 编号 | 问题 | 需求 |
|---|---|---|
| A-pull | Obsidian 端修改只在笔记本地脏时才被拉回 | 每次同步增加「拉取阶段」：对所有已同步且本地未修改的笔记，按远端文件夹用一次 PROPFIND 拿到 ETag，变化的再 GET 并合并标签与正文；ETag 不可用时用内容哈希判断。 |
| A-tagmerge | 标签是远端整体覆盖 | 三方合并：`base` = 上次同步时的标签（`SyncState.syncedTags`），`local` = 本地当前，`remote` = 远端当前。任一方删除即删除，任一方新增即新增，顺序：base 顺序 → 本地新增 → 远端新增。 |
| A-etag | PUT 不返回 ETag 的服务器会误判冲突；不返回 ETag 的服务器无法检测冲突 | 每次上传后同时记录 `remoteMdHash`（上传内容的 SHA-256）。变化判断规则：两边 ETag 都有则比 ETag；否则比哈希；都没有记录（首次连接）视为「远端有修改」。 |
| A-orphan | 改名/移动文件夹时 MOVE 失败留下孤儿文件 | MOVE 失败时把旧路径登记为待清理（复用墓碑机制，键为 `<noteId>-cleanup-<时间戳>`），本次同步结束前及下次同步开始时执行 DELETE。笔迹目录 MOVE 失败时本次重新上传全部附件。 |

### 3.3 识别（子系统 B）

| 编号 | 问题 | 需求 |
|---|---|---|
| B-lines | 整页笔迹作为一条 Ink 送 ML Kit | 先按行分组（纯算法 `LineGrouper`：按笔画包围盒的垂直重叠聚类，保持书写顺序），每行分别识别，结果按行从上到下用换行连接。 |
| B-lang | 识别语言硬编码简体中文 | 设置页新增「识别语言」选择：简体中文、繁体中文、英语、日语。切换后重建识别器，「下载模型」按钮下载当前语言模型。 |

### 3.4 组织与自动同步（子系统 C）

| 编号 | 问题 | 需求 |
|---|---|---|
| C-folder | 文件夹无法重命名/删除 | 主界面「文件夹」视图长按文件夹头部：重命名（含子文件夹前缀整体改名）、解散（笔记移到收件箱）。受影响笔记 `updatedAt` 更新，下次同步自动 MOVE。 |
| C-quickedit | 主界面无法直接改标题/标签/文件夹 | 主界面长按笔记菜单增加「编辑标题、文件夹、标签」，复用 `dialog_edit_note` 布局。 |
| C-autosync | 没有任何自动同步 | 设置项「离开编辑器后自动同步」（默认开）。退出编辑器、回到主界面时，若已配置 WebDAV、有网络、存在待同步笔记、距上次自动同步 ≥ 60 秒，则在后台执行一次同步。与手动同步互斥。 |

## 4. 暂不处理（记录原因）

| 问题 | 原因 |
|---|---|
| 撤销历史离开编辑器后丢失 | 与主流笔记应用行为一致；持久化撤销栈需要改动 `EditHistory` 与存储格式，收益不明确。 |
| 旧坐标迁移依赖当前画布尺寸（`migrateLegacyCoords` 的 51dp 经验值） | 只影响 v0.1.x 创建的笔记，且迁移只发生一次；需要真机才能验证，不在本轮范围。 |
| 页面尺寸固定为创建时的画布大小 | 属于设计取舍，改动涉及全部渲染路径。 |
| 非文石墨水屏的「通用闪刷」效果无保证 | 纯硬件行为，无法在没有掌阅/汉王真机的情况下验证。建议 README 措辞改为「尝试触发」。 |
| 翻页自动识别在笔画 ID 变化时重跑整页 | 内容变了就重识别是正确行为；按行分组（B-lines）后单次识别成本已下降。 |

## 5. 验收标准

1. `./gradlew testDebugUnitTest` 全部通过，新增测试覆盖每个需求的核心逻辑。
2. 在模拟器上：配置一个 WebDAV（可用本机 `rclone serve webdav` 或坚果云），完成「新建 → 写 → 同步 → 清空应用数据 → 从云端恢复」全流程，笔迹、图片、录音都回来。
3. 在 Obsidian 里改标签、加正文，设备端不做任何修改，点同步后本地看到远端修改；设备端加的标签在下一次同步后出现在 Obsidian。
4. 上锁的笔记，用其识别文字搜索不命中，用标题搜索命中。
